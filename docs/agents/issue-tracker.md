# Work tracker: local Markdown

Specifications, implementation tickets, and their status live in `docs/specs/` and `docs/tickets/`. Do not create GitHub Issues unless the user explicitly asks.

## Conventions

- **Create a specification**: add a Markdown document under `docs/specs/` using a descriptive, stable filename.
- **Create a ticket**: add one Markdown document per ticket under `docs/tickets/`, including its status, acceptance criteria, and blocking tickets.
- **Read work**: inspect the relevant local Markdown documents before changing code.
- **Update work**: edit the local document in the same change set as the decision or implementation it records.
- **Close a ticket**: mark it complete only after its acceptance criteria have been verified.

## When a skill says "publish to the issue tracker"

Write the requested document under `docs/specs/` or `docs/tickets/`, whichever matches the requested work.

## When a skill says "fetch the relevant ticket"

Read the applicable local ticket document.
